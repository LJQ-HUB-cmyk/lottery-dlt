## 三条设计原则

**一、时间不可伪造。**
预测写入 append-only 哈希链，每条含前一条的 SHA-256。链头提交
OpenTimestamps，落进比特币区块。「我早就算出来了」不再是嘴上说的——
是比特币替你作证，或者当场戳穿你。

**二、随机是必选项。**
`random` 基线强制在场，与其它算法同场竞技，同样参与显著性检验。
没有基线，「准」就是个没有分母的形容词。

**三、输赢全留。**
没有删除接口。开奖后自动结算，命中率与 ROI 一起写死在链上。

**推论：一条开奖后才生成的预测，宁可不要。**
数据源发布有延迟（开奖 20:30，发布可能 21:00）。若在这半小时里锁定
「下一期」，`created_at` 会晚于开奖时刻。你知道模型没看到结果，但外部
验证者只看得到时间戳，无从区分诚实延迟和事后补写——那条记录作为证据
就是零价值，而链上不可撤销。所以开奖时刻已过就抛 `DrawAlreadyHeld`
拒绝写入（[src/track.py](src/track.py)）。**宁可漏一期，也不留一条
无法自证清白的记录。**

### 第 1 步：自己复算哈希链

预测记录在 `data/predictions-{dlt,ssq}.jsonl`，一行一条。
每条的 `hash` = SHA-256 of

```
json.dumps({lottery, issue, algo, front, back, created_at, based_on, prev_hash},
           sort_keys=True, ensure_ascii=False)
```

第一条的 `prev_hash` 是 64 个 `0`，之后每条接上一条的 `hash`。
下面这段是完整的独立校验器，**只用标准库**，不 import 本项目任何东西：

```python
import hashlib, json, sys

prev, n = "0" * 64, 0
for line in open(sys.argv[1], encoding="utf-8"):
    if not line.strip():
        continue
    r = json.loads(line)
    h = hashlib.sha256(json.dumps({
        "lottery": r["lottery"], "issue": r["issue"], "algo": r["algo"],
        "front": r["front"], "back": r["back"],
        "created_at": r["created_at"], "based_on": r["based_on"],
        "prev_hash": prev,
    }, sort_keys=True, ensure_ascii=False).encode()).hexdigest()
    assert r["prev_hash"] == prev, f"第 {n} 条 prev_hash 对不上"
    assert r["hash"] == h, f"第 {n} 条 hash 对不上"
    prev, n = h, n + 1
print(f"OK  {n} 条记录，链完整\n链头 {prev}")
```

存成 `verify.py`，然后：

```bash
python3 verify.py data/predictions-dlt.jsonl
```

任何一条记录被改过——号码、时间、期号——断言会当场失败。

## 预测模型的构造

每个算法只做一件事：**给每个号码打分**，取分最高的前 N 个。
底层是 `期数 × 号码` 的 0/1 矩阵（大乐透 2905 × 35），全部配置驱动，
不含彩种硬编码。

| 算法 | 打分逻辑 |
|---|---|
| **热号** | 近 100 期出现次数，越多分越高 |
| **冷号** | 同上取反，越少分越高 |
| **遗漏值** | 距上次出现隔了多少期，越久分越高 |
| **回归周期** | 当前遗漏 ÷ 该号**自己的**历史平均间隔 |
| **马尔可夫转移** | 由「上期出 A → 本期出 B」的转移矩阵，用上期实际号码加权 |
| **和值回归** | 偏好能把本期和值拉回历史均值的号码 |
| **机器学习** | 随机森林，二分类「号码 j 下期会不会出」 |
| **堆叠模型** | 把上述算法的评分当特征，让随机森林自己学权重 |
| **随机** | 对照基线，期号做种子（可复现，防止事后挑好看的） |

**注意第 1 行和第 2 行。** 热号说「常出的还会出」，冷号说「不出的该出了」，
它们是同一个数组取反，数学上完全对立。两个都在跑——把赌徒谬误和热手谬误
摆到同一张公开记分牌上，让数据来判。

**堆叠模型**是对「你们模型太简陋、权重还是手拍的」这一反驳的正面回应。
原来的混合模型权重（`ml×2 + 热号 + 遗漏 + 马尔可夫 + 周期`）是手工拍的，
没有依据；堆叠模型让随机森林从历史里学。一个认真做的集成模型**也失败**，
比从来没试过强得多。

> 冷号故意不进堆叠特征：它是热号的单调递减变换，而决策树对单调变换不变，
> 加进去信息量严格为零。

## 空对照实验

```bash
.venv/bin/python -m src.cron null
```

用 numpy 生成一份**等概率无放回**的合成开奖——这是「绝对随机」的操作性
定义：不去假设某台摇奖机随机，而是用一个**已知随机**的过程造数据当基准
——喂给同一个堆叠模型，比较它学到了什么。

| | 大乐透 | 双色球 |
|---|---|---|
| 期数 | 2,905 | 3,485 |
| **特征重要性相关系数** | **r = 0.9745** | **r = 0.9940** |
| 最大特征差异 | 0.0326 | 0.0121 |

**模型从纯噪声里学到的结构，和它从真实彩票里学到的，是同一个东西。**

还有一个每次都出现的现象：

```
样本内概率区间  0.088~0.276     ← 看起来学到了很多
样本外概率区间  0.127~0.153     ← 塌回基准率 0.1429
```

训练集上敢给宽分布，一到预测下一期就压回均匀。**这是拟合噪声的指纹**，
真实数据和合成随机数据上同时出现。

## 显著性怎么判定

一台以「不许赖账」为唯一存在理由的机器，最容易说谎的地方，就是把一个
纯属运气的好成绩盖章成「显著优于随机」。这里做了四件事：

**一、用精确零分布，不用经验基线。**
随便选 5 个号、开奖开 5 个号，命中数服从超几何分布——这是**组合学事实，
不需要估计**。前区后区独立，卷积得总命中数分布，n 注再用二分幂卷积。
拿只有几期样本的 `random` 基线做 t 检验，等于用一把抖动的尺子量另一把。

**二、Holm–Bonferroni 控制族错误率。**
9 个算法各用 p<0.05，实测族错误率 26.1%——每个单项看起来都合规，
这是最隐蔽的一种说谎。校正后 4.7%。

**三、`random` 也参与检验。**
它是对照组，不是豁免对象。如果连它都被判「显著优于随机」，说明检验坏了。

**四、检验工具本身先过校准**（[tests/test_statistics.py](tests/test_statistics.py)）：

| 检查 | 结果 |
|---|---|
| 零分布 vs 超几何理论 | 四个彩种偏差全部 **0.00e+00** |
| p 值校准（2 万次随机预测） | 名义 0.05 → 实测 **0.0249** |
| 多重比较（9 算法 × 2000 次） | 校正前 26.1% → Holm 后 **4.7%** |
| 堆叠增量特征 vs 原算法 | 两彩种前后区偏差全部 **0.00e+00** |

p 值偏保守是离散统计量的必然，而且**方向正确**——宁可漏报，不可谎报。

### 需要多少期才能下结论

大乐透前区随便选 5 个，命中数期望 0.714、标准差 0.735。要在统计上分辨出
某算法确实更强（α=0.05，功效 80%）：

| 算法优势 | 需要期数 | 折算时间 |
|---|---|---|
| 强 50% | 33 期 | 2 个月 |
| 强 20% | 208 期 | 1 年 |
| 强 10% | 830 期 | **5 年** |
| 强 5% | 3,320 期 | **21 年** |
| 强 1% | 83,012 期 | **532 年** |

所以**累计验证做不到「证明某算法有效」**——如果开奖真是无记忆的，
那一天永远不会到来。它做的是另一件事：**把优势的天花板一点点压低**。
跑一年能说「若存在优势，它小于 20%」；跑五年，「小于 10%」。
这是排除法，不是证明法。

而且返还率是写死的 50%——哪怕真有 10% 的命中优势，离回本也差着十万八千里。

> **还有一层：**「彩票绝对随机」不是数学定理，是**关于一台物理机器的经验
> 假设**。球会磨损、重量会漂移——这正是各地彩票中心要定期换球称重的原因。
> 若那台机器真有偏差，唯一能发现它的方法就是长期累计数据做统计检验。
> 所以这套系统还有第二重身份：它不只在验证算法，**也在验证摇奖机**。

## 自动化流程

本机 launchd 每天 **09:00** 跑一次（**15:00** 兜底），
[scripts/autorun.sh](scripts/autorun.sh) 六步：

```
抓开奖结算 → 锁定下期 → 锚定比特币 → 校验哈希链 → 空对照 → 推送 GitHub
```

**为什么选上午？** 它离所有开奖时刻都远：昨晚的结果必定已发布，今晚的
开奖还有 11 小时以上。抓取端不会撞上「已开奖但未发布」的空窗，写入端有
充足余量。原来每 3 小时跑一次是在追「尽快抓到开奖」，方向错了——
正确做法是**躲开那个时刻**。

锚定紧接锁定执行，所以今天锁的预测在**今晚开奖前十几小时**就进入比特币，
证据强于「开奖后才确认」。

链校验不通过就**不推送**——不让可疑数据流到公开仓库。
中国两个彩种最短间隔 2 天（约 47 小时），每天跑一次有两倍余量。

> GitHub Actions 的定时任务已停用，只保留手动触发。哈希链必须只有一个
> 写入方，两处同时写会产生互相冲突的链头，而链断了不是 merge 能修的。

## 换个靶子：个人判断校准

同一台机器，答案未知的版本。

彩票的价值在于**答案已知**（随机），用来证明这台机器是准的。证完之后，
它可以指向任何「我在事前说过什么」需要被验证的地方——投资判断、模型
声明、科研预注册。这里先做最小的一个：**你自己的判断**。

```bash
python -m src.forecast_cli add "比特币年内破 15 万" 0.35 2026-12-31 \
    "以 CoinGecko 日收盘价为准，任意一天 ≥150000 USD 即为真"
python -m src.forecast_cli anchor      # 进比特币时间戳
python -m src.forecast_cli settle f0001 yes "11-02 收盘 151203"
python -m src.forecast_cli score
```

三条性质与彩票链一致：写在前面、有基线、输赢全留。计分用 **Brier 分数**，
并对照一个「只知道基础发生率、对每件事报同一个数」的参考模型——
技巧分 `BSS = 1 - BS/BS_ref` 大于 0，才说明你的判断带来了信息。

### 这里最脆弱的一环不是密码学，是结算

彩票的「什么算对」是免费的——号码对上就是对上，没有解释空间。
换成现实判断，只要判定标准留一条缝，人就会在事后往对自己有利的方向
解释，**而且是无意识的**。那时哈希链完好无损，记录的却是一句可以
随便解释的话。**这才是这套东西真正的失败模式。**

所以写入端设了守卫（[src/forecast.py](src/forecast.py)）：

| 拒绝 | 为什么 |
|---|---|
| 信心度 0 或 1 | 那不是预测，且 Brier 分数无法惩罚 |
| 判定标准少于 8 字 | 标准含糊 = 事后可随意解释 |
| 揭晓日已过去 | 对已发生的事记「预测」无法自证清白 |
| 二次结算 | 链是 append-only，改判等于断链 |

判定标准和判断一起锁进链；结算本身也是一条链上记录，带自己的时间戳。
改错了只能记一条新判断，不能改旧的。

# 技术部分：马尔可夫性检验

## 结论：开奖序列没有可检出的记忆

数据 2903 期（2007-05-30 ~ 2026-07-29）。用聚合特征定义状态，
似然比 G² 检验 H₀=零阶（独立）vs H₁=一阶马尔可夫：

| 状态定义 | G² | 自由度 | p 值 |
|---|---|---|---|
| 前区和值 (5态) | 15.084 | 16 | 0.519 |
| 奇数个数 (4态) | 4.151 | 9 | 0.901 |
| 大号个数 (4态) | 4.725 | 9 | 0.858 |
| 主导区间 (3态) | 5.391 | 4 | 0.249 |
| 后区和值 (3态) | 4.652 | 4 | 0.325 |

BH 法 FDR 校正后，**5 个检验全部无法拒绝 H₀**。

**这个负结果之所以有意义，是因为检验先通过了校准**
（[tests/test_calibration.py](tests/test_calibration.py)）：

- 喂 200 组确定独立的数据 → 误报率 0.030（期望 0.05），KS 检验 p=0.678
- 喂确定有记忆的数据 → 记忆强度 eps=0.10 时**检出率 99%**，eps≥0.20 时 100%

也就是说这个工具**有能力**发现 eps≥0.10 量级的记忆效应，它在真实数据上
没发现，说明真实记忆效应（若存在）小于这个量级。没有这一步，「未检测到」
可能只是工具太弱，毫无信息量。

推论：冷热号、遗漏值这类建立在「上期影响下期」之上的理论，在这批数据上
没有统计支持。

# 技术部分：Lottery Wheel

覆盖设计 C(v,5,t)：圈 v 个前区号，保证开奖号中任意 t 个落在池内时必有一注命中。

**wheel 不改变期望回报**（N 注的期望恒等于 N × 单注期望），它改变的是
概率分布的形状：把「可能颗粒无收」的质量挪到「条件满足即必中」上。
**这是方差管理，不是收益提升。**

```bash
python -m src.cli wheel --pool 9 --guarantee 3 --back 3
python -m src.cli wheel --pool 10 --guarantee 3 --show
python -m src.cli wheel --pool 9 --guarantee 3 --back 3 --analyze 200000
```

以圈 9 个前区号 + 3 个后区号为例：

```
注单：36 注，成本 72 元    （C(9,5,3)=12 注 × C(3,2)=3）

保证条件触发概率（精确计算）：
  5 个前区号中 ≥3 个落在你圈的 9 个里       9.4575%
  2 个后区号都落在你圈的 3 个里             4.5455%
  两者同时满足（保证生效）                   0.4299%   → 平均每 233 期一次

期望回报（精确计算）：
  单注期望  1.1993 元（成本 2 元）    真实 ROI  -40.0%

模拟 20 万期的分布：
  中位数 0 元    75% 分位 15 元    颗粒无收 74.5%
```

花 72 元，74.5% 的期数一分钱不中，那个「必中六等奖 200 元」的保证平均
233 期才触发一次。**真实 ROI 恒为 −40%，任何选号方式都改不动它。**

## 求解结果

| 配置 | Schönheim 下界 | 贪心 | 循环群 | 退火 | ILP 最优 |
|---|---|---|---|---|---|
| C(8,5,3) | 7 | 9 | **8** | 8 | **8**（已证明） |
| C(9,5,3) | 11 | **12** | 18 | 12 | **12**（已证明） |
| C(10,5,3) | 14 | 19 | 20 | **17** | **17**（已证明，约 40 分钟） |
| C(9,5,4) | 26 | 32 | **30** | 30 | 未跑 |

**循环群构造在 v=8 时赢了贪心**（8 vs 9）——代数结构确实起了作用；
**退火把 C(10,5,3) 从 19 压到 17**。

### 关键发现：差距主要来自下界不紧

一开始把 17 vs 14 的差距当成「构造不够好」，于是上 ILP 精确求解（HiGHS）。
结果推翻了这个解读：

- **C(8,5,3) 的真实最优是 8，不是下界给的 7** —— 循环构造早已触顶
- **C(9,5,3) 的真实最优是 12，不是 11** —— 贪心结果就是最优解
- **C(10,5,3) 的真实最优是 17，不是 14** —— HiGHS 约 40 分钟后对偶界收敛到 17
  （Status 7: Optimal），即 16 注的构造不存在。**这是证明，不是「没搜到」**

三个配置无一例外：启发式给出的解全都是最优解，**全部 gap 都来自 Schönheim
下界不紧**，没有一注是搜索能力不足造成的。

Schönheim 下界只是一个**未必可达的理论界**。把启发式结果与它的差距直接
当作改进空间，会追逐一个根本不存在的目标。

covering"——与本项目退火所得一致。该页面**未声明该构造已被证明最优**。

## 关于挂谷猜想

这个项目源于一场关于挂谷猜想能否用于彩票的讨论。诚实的结论：

**王虹与 Zahl 2025 年证明的三维挂谷猜想，无法应用到彩票。** 它是实分析／
几何测度论的结果，研究连续空间中不可数集合的豪斯多夫维数；而彩票是有限
离散问题，豪斯多夫维数在有限集上恒为 0，这个概念在此退化成平凡的。
中间没有桥。

**但有一条真实的相邻血脉**：Wolff 1999 提出的有限域版本 Kakeya 猜想，
被 Dvir 2009 用多项式方法证明，那一支属于货真价实的组合数学。而**有限
几何**——既是有限域 Kakeya 的舞台，也是覆盖设计的经典构造来源。本项目
`wheel.cyclic()` 用的 Z_v 循环群构造正出自这个工具箱，它在 C(8,5,3) 上
确实赢了贪心。

所以：挂谷猜想的**结论**用不上，但它所在的**工具箱**里有东西能真正改进 wheel。

## 设计要点

**为什么摘要文件必须写一次即冻结**：OpenTimestamps 承诺的是**文件字节**的
SHA-256，而摘要文件名只由记录数和链头决定、内容里却有 `created_at`。
同一链头第二次生成时若重新写入，字节变了，之前盖的章当场失配，
**而且没有任何报错**。这个 bug 真实发生过并已修复——失效那份凭证靠锚定
日志里留存的原始 `created_at` 逐字节复原，重建文件的 SHA-256 与凭证承诺值
完全相同（属自证）。现已由测试钉死。

**为什么方案 B 而不是直接估转移矩阵**：前区状态空间是 C(35,5)=324,632，
转移矩阵约 1054 亿格，而数据只有 2903 期——每格平均 0.0000003 个观测，
估出来全是噪声。必须降维到聚合特征，让每格期望频数够大（本项目最低 57.6）。

**为什么必须做多重比较校正**：同时检验多个假设，即使全部无效也会冒出
「发现」。`markov.py` 用 BH 控制 FDR，`track.py` 用 Holm 控制 FWER——
后者更严，因为「谎报某算法有效」的代价远高于漏报。

**为什么校准测试是前提而非补充**：一个永远输出「无显著差异」的检验和一个
正确的检验，在负结果上看起来一模一样。只有先证明它有功效，负结果才是结论。

**为什么启发式之外还要跑 ILP**：贪心／退火只能给出「我找到了这么多注」，
永远无法回答「还能不能更少」。ILP 返回 optimal 时给的是被证明的最优值——
这是区分「构造不力」与「下界不紧」的唯一手段，而这两者需要的后续动作完全相反。

**为什么期望值必须精确算而不能用模拟**：本项目第一版用蒙特卡洛均值报 ROI，
20 万期模拟里恰好撞出一次头奖，直接报出 **+16.3% 的正收益**——完全是假象。
奖金分布是重尾的，一个极端样本就能主导均值。改用超几何分布精确计算后，
真实 ROI 是 **−40.0%**。模拟只用来看分布形状，均值一律以解析解为准。

**wheel 不改变期望，这是恒等式而非经验**：期望具有线性性，N 注注单的总期望
恒等于 N × 单注期望，与这 N 注如何构造完全无关。所以任何声称「通过选号方式
提高期望回报」的说法，在数学上是被排除的。
